Ottimizzazione dei Costi nel Cloud: Strategie e Strumenti

Gabriel Rovesti
Full Stack Developer & Educator

Analizziamo metodologie e strumenti per ottimizzare i costi delle infrastrutture cloud, con focus su AWS e GCP, automazione e rightsizing. Questo articolo è frutto della mia esperienza nel gestire infrastrutture cloud per progetti di varie dimensioni e complessità.

La sfida della gestione dei costi cloud

Con l'adozione sempre più diffusa del cloud computing, molte organizzazioni si trovano ad affrontare una sfida significativa: il controllo dei costi. Secondo Gartner, fino al 70% della spesa cloud nelle aziende è sprecata a causa di risorse sovradimensionate, istanze inattive e mancanza di governance.

Questo fenomeno ha dato origine a una nuova disciplina chiamata FinOps (Cloud Financial Operations), che combina competenze finanziarie, tecniche e organizzative per ottimizzare gli investimenti nel cloud.

Principi fondamentali di FinOps

Prima di addentrarci nelle strategie specifiche, è importante comprendere i principi chiave che guidano un'efficace gestione dei costi cloud:

  • Visibilità e allocazione: Tracciare accuratamente le spese e allocarle ai team o ai progetti responsabili
  • Ottimizzazione: Identificare e implementare opportunità di risparmio senza compromettere prestazioni o sicurezza
  • Previsione: Stimare i costi futuri per pianificare budget e investimenti
  • Responsabilità condivisa: Coinvolgere tutti i team nel controllo dei costi, non solo il reparto IT o finanziario

Strategie di ottimizzazione per AWS

Amazon Web Services (AWS) offre numerose possibilità di ottimizzazione dei costi. Ecco le strategie più efficaci che ho implementato:

1. Rightsizing delle istanze EC2

Il rightsizing è il processo di adattamento delle risorse alle effettive necessità dell'applicazione. Per le istanze EC2, ciò significa analizzare l'utilizzo effettivo di CPU, memoria e I/O per identificare istanze sovradimensionate. 

# Script Python per analizzare l'utilizzo CPU di istanze EC2 con boto3
import boto3
import datetime

def get_ec2_cpu_utilization(instance_id, region, days=14):
    # Crea il client CloudWatch
    cloudwatch = boto3.client('cloudwatch', region_name=region)
    
    # Calcola periodo di analisi
    end_time = datetime.datetime.utcnow()
    start_time = end_time - datetime.timedelta(days=days)
    
    # Ottieni metriche CPU
    response = cloudwatch.get_metric_statistics(
        Namespace='AWS/EC2',
        MetricName='CPUUtilization',
        Dimensions=[{'Name': 'InstanceId', 'Value': instance_id}],
        StartTime=start_time,
        EndTime=end_time,
        Period=3600,  # 1 ora
        Statistics=['Average', 'Maximum']
    )
    
    if len(response['Datapoints']) == 0:
        return None
    
    # Analizza i risultati
    datapoints = response['Datapoints']
    avg_cpu = sum(point['Average'] for point in datapoints) / len(datapoints)
    max_cpu = max(point['Maximum'] for point in datapoints)
    
    # Determina se l'istanza è candidata per il downsizing
    recommendation = None
    if avg_cpu < 5 and max_cpu < 10:
        recommendation = "Forte candidata per ridimensionamento o eliminazione"
    elif avg_cpu < 10 and max_cpu < 20:
        recommendation = "Candidata per downsizing"
    elif avg_cpu < 30 and max_cpu < 50:
        recommendation = "Considerare famiglia di istanze ottimizzata per costi"
    
    return {
        'instance_id': instance_id,
        'avg_cpu': avg_cpu,
        'max_cpu': max_cpu,
        'recommendation': recommendation
    }

2. Savings Plans e Istanze Riservate

Gli impegni a lungo termine con AWS possono portare a risparmi significativi rispetto ai prezzi on-demand:

  • Savings Plans: Impegno di spesa oraria per 1 o 3 anni con risparmi fino al 72%
  • Istanze Riservate: Prenotazione di capacità specifica con sconti fino al 75%

La mia analisi su diversi progetti ha dimostrato che una combinazione ottimale è:

  • 60-70% della capacità coperta da impegni a lungo termine (workload prevedibili)
  • 20-30% con istanze spot (workload tolleranti alle interruzioni)
  • 10-20% on-demand (per picchi imprevisti e carichi di lavoro critici)

3. Automazione con AWS Lambda

L'automazione è fondamentale per un'efficace gestione dei costi. Ecco un esempio di funzione Lambda che spegne automaticamente le istanze di sviluppo durante le ore non lavorative: 

import boto3
import datetime

def lambda_handler(event, context):
    # Verifica se è orario lavorativo
    now = datetime.datetime.now()
    is_weekend = now.weekday() >= 5  # 5 = sabato, 6 = domenica
    is_work_hours = 8 <= now.hour < 19  # ore 8:00-19:00
    
    # Non fermare istanze durante orario lavorativo nei giorni feriali
    if not is_weekend and is_work_hours:
        print("Orario lavorativo, nessuna azione richiesta")
        return
    
    # Connessione a EC2
    ec2 = boto3.resource('ec2')
    
    # Cerca istanze di sviluppo in esecuzione (tag Environment=Development)
    instances = ec2.instances.filter(
        Filters=[
            {'Name': 'tag:Environment', 'Values': ['Development']},
            {'Name': 'instance-state-name', 'Values': ['running']}
        ]
    )
    
    # Ferma le istanze
    instance_ids = [instance.id for instance in instances]
    if instance_ids:
        ec2.instances.filter(InstanceIds=instance_ids).stop()
        print(f"Fermate istanze: {instance_ids}")
    else:
        print("Nessuna istanza di sviluppo in esecuzione")
"Ottimizzare i costi cloud non significa semplicemente ridurre la spesa, ma massimizzare il valore ottenuto per ogni euro investito. L'obiettivo è spendere consapevolmente, non necessariamente meno."

Strategie di ottimizzazione per Google Cloud Platform

Anche Google Cloud Platform (GCP) offre diversi strumenti e tecniche per ottimizzare i costi:

1. Committed Use Discounts (CUD)

Simili ai Savings Plans di AWS, i CUD offrono sconti significativi in cambio di impegni di utilizzo a 1 o 3 anni. Una particolarità di GCP è che gli sconti si applicano automaticamente alle risorse idonee, semplificando la gestione rispetto ad AWS.

2. Utilizzo dello strumento Recommender

GCP offre uno strumento integrato, Recommender, che fornisce suggerimenti proattivi per ottimizzare le risorse:

  • Identificazione di VM inattive o sottoutilizzate
  • Ridimensionamento di dischi persistenti
  • Suggerimenti sui Committed Use Discounts ottimali
  • Raccomandazioni per ottimizzare BigQuery

3. Automazione con Cloud Functions e Pub/Sub

L'architettura serverless di GCP può essere sfruttata per implementare controlli automatici dei costi: 

from google.cloud import compute_v1, pubsub_v1
import datetime
import base64
import json

def handle_budget_alert(event, context):
    """Gestisce gli avvisi di budget reagendo in base alla gravità"""
    
    # Decodifica il messaggio Pub/Sub
    pubsub_message = base64.b64decode(event['data']).decode('utf-8')
    budget_data = json.loads(pubsub_message)
    
    # Estrai le informazioni rilevanti
    cost_amount = budget_data.get('costAmount')
    budget_amount = budget_data.get('budgetAmount')
    threshold_exceeded = budget_data.get('alertThresholdExceeded')
    
    # Calcola la percentuale del budget utilizzata
    if budget_amount > 0:
        usage_percentage = (cost_amount / budget_amount) * 100
    else:
        usage_percentage = 0
    
    # Log dell'evento
    print(f"Budget alert: {usage_percentage:.2f}% del budget utilizzato")
    
    # Azioni basate sulla percentuale di utilizzo
    if usage_percentage >= 90:
        # Azione drastica - ferma tutte le risorse non di produzione
        stop_non_production_resources()
    elif usage_percentage >= 80:
        # Azione intermedia - ferma le risorse di sviluppo
        stop_development_resources()
    elif usage_percentage >= 70:
        # Azione preventiva - invia notifica dettagliata
        send_detailed_alert(cost_amount, budget_amount, usage_percentage)
        
def stop_non_production_resources():
    """Ferma tutte le risorse che non sono di produzione"""
    
    # Inizializza il client Compute Engine
    client = compute_v1.InstancesClient()
    
    # Elenca tutte le zone disponibili
    regions_client = compute_v1.RegionsClient()
    project_id = "your-project-id"  # Sostituire con l'ID del progetto
    
    # Ottieni tutte le regioni
    request = compute_v1.ListRegionsRequest(project=project_id)
    regions = regions_client.list(request=request)
    
    # Per ogni regione, ferma le istanze non di produzione
    for region in regions:
        # Ottieni le zone nella regione
        zones = [zone.split('/')[-1] for zone in region.zones]
        
        for zone in zones:
            # Lista istanze nella zona
            request = compute_v1.ListInstancesRequest(
                project=project_id,
                zone=zone,
                filter="labels.environment!=production"
            )
            
            try:
                instances = client.list(request=request)
                for instance in instances:
                    if instance.status == "RUNNING":
                        # Ferma l'istanza
                        stop_request = compute_v1.StopInstanceRequest(
                            project=project_id,
                            zone=zone,
                            instance=instance.name
                        )
                        client.stop(request=stop_request)
                        print(f"Fermata istanza: {instance.name} in {zone}")
            except Exception as e:
                print(f"Errore nel processare la zona {zone}: {e}")

Strumenti di terze parti per ottimizzazione multi-cloud

Oltre agli strumenti nativi dei fornitori cloud, esistono soluzioni di terze parti che possono aiutare nell'ottimizzazione dei costi, particolarmente utili in ambienti multi-cloud:

1. CloudHealth by VMware

CloudHealth offre una visione unificata delle spese cloud attraverso diversi provider, con funzionalità avanzate per:

  • Allocazione dei costi per team, progetti o centri di costo
  • Identificazione di anomalie di spesa
  • Automazione di policy di ottimizzazione
  • Reportistica personalizzabile per diverse parti interessate

2. Kubecost per ambienti Kubernetes

Per chi utilizza Kubernetes su qualsiasi cloud, Kubecost offre visibilità granulare sui costi a livello di:

  • Namespace
  • Deployment
  • Service
  • Pod
  • Label personalizzate

È particolarmente utile per comprendere i costi effettivi delle applicazioni containerizzate e identificare opportunità di ottimizzazione a livello di microservizi.

Strategie organizzative e culturali

Le tecnologie e gli strumenti sono solo una parte dell'equazione. Per una gestione efficace dei costi cloud, sono necessari anche cambiamenti organizzativi e culturali:

1. Responsabilità condivisa

Implementare un modello di "chargeback" o "showback" in cui i team sono consapevoli e responsabili dei costi generati dalle loro risorse cloud.

2. Formazione continua

Assicurarsi che i team comprendano le implicazioni finanziarie delle loro decisioni tecniche attraverso:

  • Workshop su FinOps
  • Revisioni periodiche dei costi
  • Documentazione e linee guida interne

3. Integrazione nei flussi di CI/CD

Incorporare controlli di costo nei processi di Continuous Integration e Continuous Delivery:

  • Analisi statiche di Infrastructure as Code (IaC) per identificare configurazioni costose
  • Previsioni di costo pre-deployment
  • Limiti di approvazione per risorse che superano determinate soglie di costo

Case study: Ottimizzazione di un'infrastruttura data analytics

In un recente progetto, ho aiutato un'azienda a ottimizzare la sua infrastruttura di analytics su AWS, ottenendo un risparmio del 42% sui costi mensili senza compromettere le prestazioni. Ecco le principali ottimizzazioni implementate:

  1. Migrazione da RDS a Aurora Serverless: Per carichi di lavoro intermittenti, con risparmi del 60% grazie al pagamento solo per il tempo di utilizzo effettivo
  2. Implementazione di lifecycle policy per S3: Transizione automatica dei dati meno recenti da S3 Standard a S3 Glacier Deep Archive
  3. Rightsizing dei cluster EMR: Passaggio a istanze ottimizzate per memoria e implementazione di autoscaling basato sui job
  4. Schedulazione automatica: Spegnimento automatico degli ambienti di sviluppo e test durante le ore non lavorative
  5. Consolidamento dei log in CloudWatch Logs Insights: Riduzione dei costi di archiviazione e analisi dei log

Metriche chiave per il monitoraggio dei costi

Infine, è fondamentale monitorare costantemente alcune metriche chiave per verificare l'efficacia delle strategie di ottimizzazione:

  • Costo per unità di lavoro: Ad esempio, costo per richiesta API, per utente attivo o per transazione
  • Percentuale di copertura con impegni: Proporzione di risorse coperte da Savings Plans, Istanze Riservate o CUD
  • Trend di utilizzo vs. trend di costo: Per identificare inefficienze quando i costi crescono più rapidamente dell'utilizzo
  • Costo per team o servizio: Per identificare quali aree dell'organizzazione offrono opportunità di ottimizzazione

L'ottimizzazione dei costi cloud è un processo continuo, non un progetto una tantum. Con i giusti strumenti, processi e una cultura di responsabilità condivisa, è possibile ottenere significativi risparmi mantenendo o addirittura migliorando le prestazioni e l'affidabilità dei sistemi.
